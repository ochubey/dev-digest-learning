## 3. How to reproduce these numbers

```bash
cd /Users/oleksiychubey/dev-digest-learning
git log --merges --first-parent --oneline main          # find merge commits
# #21 cb25b83, #22 6d6d566, #23 5ad0b02, #24 b671aa8
git rev-parse main origin/main && git merge-base main feat/design-gaps   # all b671aa8

# per PR (M = merge commit): per-file and total
git diff -M --numstat M^1 M
git diff -M --shortstat M^1 M

# unmerged branch
git diff -M --numstat main...feat/design-gaps
git diff -M --shortstat main...feat/design-gaps
git log --oneline main..feat/design-gaps

# category split: sum column 1 of --numstat grouped by the path rules above
```

Cross-check: for every group the per-file sum of `--numstat` equals `--shortstat` (files, insertions, deletions) exactly: #21 21/2596/4, #22 76/8691/66, #23 97/12582/77, #24 6/19/9, branch 109/7005/307. No renames were detected with `-M` in any group (no `=>` in the output), so rename detection does not change any number. Binary files: none (no `-` entries). Merge commits' own diffs are not included; the figures are per first-parent base.

Caveats: each PR is measured against its own merge base, so the four PR numbers can be added (see the sum row in section 1; 200 file entries, a file touched by two PRs is counted in both). The same file can appear in several groups (for example `server/test/ci-export.test.ts`, created in #23 and extended on the branch). Symlink entries (`specs/export-to-ci.md`, `specs/multi-agent-review.md`) count as 1 line each.

## 4. Reading the numbers

A reviewer needs to read hand-written product code and tests. Docs and i18n are skim material; generated files should be excluded entirely (review the schema `.ts` file and the small `.sql` instead of the snapshot).

Reviewable size (hand-written product + tests, added lines) from section 1: #21 = 1,330 of 2,596; #22 = 4,016 of 8,691; #23 = 7,038 of 12,582; #24 = 5 of 19; unmerged branch = 2,560 of 7,005. Of the unmerged +7,005, the single file `0018_snapshot.json` is 4,148 lines (59% of the branch is generated), so the real hand-written change there is about 1,137 product + 1,423 test lines. To judge PR size, subtract the generated/lock column (drizzle snapshots dominate: each is about 3,900 to 4,150 lines for a handful of real schema changes) and treat specs/plans as reading material, not code to verify. Tests are real code but are mostly mechanical assertions; a ratio of roughly one test line per product line is visible in #22 and #23.
