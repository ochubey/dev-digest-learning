### 3e. Data flows

**Preview and export** (`service.ts`). The checks run in this order; nothing is written until all pass.
1. Load the agent (404). Its provider must be `openrouter`.
2. Resolve the repo by `full_name` in the workspace.
3. Validate triggers: a non-empty subset of `CI_TRIGGERS`.
4. Look up the installation for the repo:
   - another agent -> 409 `ci_repo_taken`, message "<repo> already runs agent <name> in CI; one agent per repository is supported";
   - same agent with a different slug -> 409 `ci_slug_changed`.
5. Load enabled linked skills and repo memory, read the runner (400 if missing), and build the bundle.
6. If `input.workflow` is set: run `checkWorkflow` (400 `ci_workflow_unsafe` naming the rule), then replace the generated workflow text with the user's exact text (AC-30).
7. **Zip path (`action: 'files'`):** `buildZip`, then upsert the installation with `pr_url: null`; `github_repo_id` keeps its existing value or stays null. No GitHub call (AC-47).
8. **PR path (`action: 'open_pr'`):**
   - `commitFiles({ branch: 'devdigest/ci', base: repo.defaultBranch, message: 'chore(devdigest): add DevDigest CI review', files })`
   - `findOpenPr(repo, 'devdigest/ci')`; only if it returns null, call `openPullRequest({ head: 'devdigest/ci', base: defaultBranch, title, body })`.
   - Best-effort `actions.getRepoId` (null on failure; the first sync fills it).
   - Upsert the installation and return.
   - Any GitHub error goes through `mapWriteError`; the installation is not touched (AC-49).
9. Log `exportLine` once per export (success or error).

**Sync** (`sync.ts`, `Promise.allSettled` over installations, each wrapped in `withTimeout(60 s)`). For each installation:
1. If `github_repo_id` is null, call `getRepoId` and store it (AC-60).
2. `listCompletedRuns(30)`, then drop the run ids that are already stored.
3. For each new run, one after another:
   - `downloadResultArtifact` returns null -> store a failed row "No result artifact ...";
   - `readResultArchive` or `validateArtifact` fails -> store a failed row "Result rejected: <rule>", no counts, and log `rejectLine` at warn level;
   - otherwise -> `insertRun(validRow, agentRun)` with `prId` from `findImportedPr`.
4. An error in one installation is mapped with `mapReadError` into `failures[]`; the other installations continue (AC-68).
5. Log `syncLine` once per installation.
6. Concurrent syncs are safe because of the unique `github_run_id` and the single-transaction insert (AC-67).

### 3f. agent-runner (P2)
- `context.ts`: `PrContext.headSha` from `pull_request.head.sha` (null if absent). `repositoryId` from env `GITHUB_REPOSITORY_ID` (integer or null).
- `artifact.ts`: `RUNNER_VERSION = CI_RUNNER_VERSION` from shared. New inputs `commitSha`, `repositoryId`, `model`, `agentVersion`, `verdict`, `blockers`.
- `run.ts`:
  - pass `manifest.model`, `manifest.version ?? null`, `verdict = payload.event` (deterministic), `blockers`, and the context fields;
  - redact `error` in the catch;
  - redact posted bodies and comments before posting;

## 8. Risks and assumptions

- **R1. GitHub error texts** for a missing `workflow` scope (classic and fine-grained) and for Actions read denial are mapped by message and status heuristics (`github-errors.ts`). The optional `researcher` item from the spec, or manual step 3, confirms them.
- **R2. Security note for the reviewer:** for `pull_request` events GitHub takes the workflow *definition* from the PR merge commit.
  - A same-repository PR author with write access can change the workflow for their own PR's run.
  - The base-SHA checkout protects the runner, manifest and skills only.
  - Fork PRs get no secrets and are skipped (AC-23).
  - This is accepted by A-5 and A-12. It is not covered by an AC; it should be mentioned in the PR body's checklist (T12 already lists "which commit's code runs").
- **R3. Runner version.** The preview reports `CI_RUNNER_VERSION` from the contract, not from the built file. A stale `dist/` built before P2 would ship an older artifact shape, and ingest then rejects it (`commit_sha_mismatch`). Rebuild after P2.
- **R4. CI `agent_runs` in the PR timeline.** CI runs linked to an imported PR create `agent_runs` rows with no `run_traces`. The PR run history may list them and the Run Trace drawer would find no trace (A-11 accepts this). The architecture reviewer should confirm the PR page tolerates a run without a trace. If it does not, the fix stays in `ci` (for example not setting `prId`), which needs a spec decision; do not patch worktree A's PR page.
- **R5. Branch "overwritten"** (section 2 item 3). Existing `commitFiles` keeps prior commits on `devdigest/ci`. This is accepted via A-16.
- **R6. Zip response size.** It carries the base64 runner (a few MB). This is acceptable for a local studio; `bodyLimit` only affects requests.
- **R7. New server dependency `yaml`.** `server/package.json` and the lockfile change through `pnpm add` only. Worktree A must not add a conflicting entry; if it does, resolve by re-running `pnpm install`.
- **R8. AC-91 stale Verify line** (section 0).
- **R9. Integration ACs** (AC-48, 64, 65, 67, part of 72) are only proven when Docker is present.
- **Assumptions:**
  - "Repository scoped" memory means `memory.repo_id = <selected repo>`.
  - `github_repo_id` fits in a JS number.
  - The sync runs workspace-wide from both the CI Runs page and the CI tab.
  - "Last synced" is client state, not persisted.
  - The `ci.json` namespace stays unused.
  - The `specs/export-to-ci.md` symlink (OQ-1) is the caller's choice and not part of any phase.
- **Housekeeping:** `agent-runner/.gitignore.swp` is untracked in the main checkout. Do not commit `.swp` files.
