## Codebase Patterns

- `AgentsRepository.skillCounts(agentIds)` mirrors `SkillsRepository.agentCounts(skillIds)` exactly (group-by count over `agent_skills`, one query for the whole list) — added for `Agent.skill_count`, wired through `AgentsService.list`/`get` → `toAgentDto(row, skillCount)`, which now takes a second optional arg (defaults to 0) instead of always computing it inline, so callers that don't have counts handy (e.g. `create`/`update`, which still call the repo's raw `toAgentDto(row)` via `service.ts`) don't need a wasted query for a freshly-created agent that can't have any links yet. `server/src/modules/agents/repository.ts:224`, `server/src/modules/agents/helpers.ts:12`. (2026-09-28)

- `reviews` denormalizes `run_id` (nullable uuid, no FK) onto itself at insert time — the PR-list "latest review" join can pull a per-run field (e.g. `agent_runs.cost_usd`) by `leftJoin(agentRuns, eq(agentRuns.id, reviews.runId))` instead of a second round-trip. `server/src/db/schema/reviews.ts:19`. (2026-09-27)
- `container.priceBook.estimate(model, tokensIn, tokensOut)` is synchronous (returns `number | null` directly, not a Promise) — safe to call inline in `run-executor.ts` right after token counts are known, no `await` needed. `server/src/platform/price-book.ts:33`. (2026-09-27)

- The app-wide error handler maps zod schema failures to 422, so a route that must answer 400 (project-context attach lists) validates only the shape in the route (`AttachBody`) and lets the service return the 400 for duplicates, bad paths and limits. `server/src/modules/project-context/routes.ts:23`. (2026-10-10)
- `run-executor.ts` holds the resolved project context (`pc`) outside the `try`, so failed and cancelled runs keep their `specs_read` entries and commit SHA; for runs with no effective documents nothing is added to the trace (no `project_context` key), keeping prompts and stored traces identical to before the feature. `server/src/modules/reviews/run-executor.ts:431`. (2026-10-10)

## Tool & Library Notes

- `app.log.debug` calls are silent by default in dev — `config.logLevel` (from `.env`) must be `debug` or lower to see them; `pino-pretty` transport only kicks in for `nodeEnv === 'development'`. `server/src/app.ts:50-59`. (2026-09-27)
- `pnpm` installed via `npm install -g pnpm` is a no-op wrapper shell script in this sandbox until its own postinstall (`install.js`, which downloads the real native binary) is allowed to run — `allowScripts` blocks it silently (exit 0, zero output, looks like success). Running `node install.js` directly from the global pnpm package dir (`npm root -g`/pnpm/install.js) fixes it in-place; after that `pnpm <script>` works normally (no need to keep using `npm run` as a workaround). `server/package.json:1`. (2026-09-27)

- `OctokitGitHubClient.readRepoFile` decodes with `Buffer.toString('utf-8')`, which silently replaces invalid bytes, so it cannot tell a binary file from text; `ProjectDocsSource.readBlob` returns raw bytes and the caller decodes strictly (`TextDecoder` with `fatal: true`) to produce the `not_text` skip reason. `server/src/adapters/project-docs/octokit.ts:94`. (2026-10-10)

## Recurring Errors & Fixes

- `pnpm db:migrate` / `pnpm db:seed` silently do NOTHING on Windows (exit 0, no output, no DB changes) — both `migrate.ts:35` and `seed.ts:227` gate their CLI entrypoint on `import.meta.url === \`file://${process.argv[1]}\``, but on Windows `process.argv[1]` is a backslash path (`E:\...`) while `import.meta.url` is a `file:///E:/...` URL — they never match, so the guarded block never runs. Workaround: write a one-off script that imports `runMigrations`/`seed` directly and calls them, instead of running the file as a CLI entrypoint. `server/src/db/migrate.ts:35`, `server/src/db/seed.ts:227`. (2026-09-27)
- `run-executor.ts` was re-deriving `costUsd` from `priceBook.estimate(agent.model, tokensIn, tokensOut)` on the summed totals, completely ignoring that `reviewer-core`'s `ReviewOutcome.costUsd` already sums per-chunk cost AND prefers OpenRouter's live billed cost (`costFromApi` in `reviewer-core/llm/openrouter.ts:107`) over the same static estimate when the provider reports one. Fixed to destructure `costUsd` straight from `outcome`. The line 10 entry above (from earlier this session) describing `priceBook.estimate` as the source of truth is now superseded by this — `outcome.costUsd` is. `server/src/modules/reviews/run-executor.ts:213`. (2026-09-27)
- The PR-list `/repos/:id/pulls` FINDINGS column (`routes.ts`) only ever pulled findings from ONE "latest review overall" per PR — same bug shape as the score fix nearby (which already dedupes per `(prId, agentId)`): a PR reviewed by 2 agents showed only the last agent's findings, silently dropping the other agent's. Fixed to track one latest review id per `(PR, agent)` and sum findings across all of them. `server/src/modules/pulls/routes.ts:121`. (2026-09-28)

- The seed runs on every dev server start (`server.ts:15`) and used to attach demo document paths (`specs/security-baseline.md`, `docs/architecture.md`) to Security Reviewer in the developer's REAL workspace, so reviews of a real repo logged `skipped … (not_found)`. Demo attachments are now opt-in (`seed(db, { demoContext })`, true only with `PROJECT_DOCS_SOURCE=fixture`); paths already attached in an existing DB must be detached by hand. `server/src/db/seed.ts:498`. (2026-10-10)

## Session Notes

- Seeded agents default to `deepseek/deepseek-v4-flash` via OpenRouter — this is a reasoning model (hidden `reasoning`/`reasoning_details` tokens billed as `completion_tokens` before any visible `content`). A real single-pass review of a 3-file/~70-line diff took 16s and 1028 completion tokens (`$0.00105`) end-to-end — noticeably slower than a plain non-reasoning flash model would be, and can look like a hang if you expect sub-5s responses; give runs 30s+ before assuming something's stuck. `server/src/adapters/llm/pricing.ts:1`. (2026-09-27)

- SUPERSEDED 2026-09-28 (Track A): `.zip` import IS now implemented via `adm-zip` (already installed). `parseSkillImport` dispatches on filename extension (`.md` vs `.zip`); `parseZipImport` requires exactly one root-level `.md` entry (any entry with `/` in its path is rejected as a nested directory), rejects any entry whose name contains `..` (path traversal) before checking anything else, and rejects symlink entries by reading the unix mode bits out of `entry.header.attr >>> 16` and checking against `S_IFLNK` (`0o120000`) — `adm-zip` does NOT expose a `isSymlink()` helper, you have to decode the packed external file attributes yourself. `server/src/modules/skills/import.ts:1`. (2026-09-28)
- `AdmZip.getEntries()[i].header.attr` packs the unix `st_mode` (permission bits + file-type bits, e.g. `S_IFLNK=0o120000`, `S_IFREG=0o100000`) into the TOP 16 bits (`>>> 16`) of the zip's "external file attributes" field — the bottom 16 bits are DOS attributes and irrelevant here. Confirmed via a hand-built zip in a unit test (`test/skills-import.test.ts`) that manually sets `entry.header.attr = (0o120000 << 16) | 0o755` to simulate a symlink entry, since `adm-zip`'s own `addFile` API has no way to add a real symlink. (2026-09-28)

- `POST /skills/:id/versions/:version/restore` mirrors `SkillsRepository.update()`'s snapshot-then-write pattern exactly: `restoreVersion()` snapshots the CURRENT body (pre-restore) into `skill_versions` first, THEN overwrites `skills.body` with the target snapshot's body and bumps `version` — so restoring to v1 from v3 does NOT delete/renumber anything, it just creates a new v4 whose body equals v1's, and the old v3 body is preserved as its own permanent snapshot. Verified live against Testcontainers Postgres in `test/skills.it.test.ts`. `server/src/modules/skills/repository.ts:113`. (2026-09-28)

- The `conventions` table has no `evidence_line` column (only `rejected` was added in prep work for this track) — rather than a new migration, the extracted line number is folded into `evidence_path` as `<path>:<line>` and split back out in `toConventionDto` (`decodeEvidencePath`). `server/src/modules/conventions/helpers.ts:1`. (2026-09-28)
- `container` has no `reposRepo` getter (unlike `agentsRepo`/`reviewRepo`) — every module that needs repo rows (e.g. `repos/service.ts`) constructs its own `new RepoRepository(container.db)` instead; conventions/service.ts does the same rather than adding a new container getter. `server/src/platform/container.ts:89`. (2026-09-28)
- `GitClient.readFile()` throws (ENOENT) on the real `SimpleGitClient` for a missing file but `MockGitClient.readFile()` always resolves (to `opts.files[path] ?? ''`) — sample-collection code that relies on try/catch-to-skip-missing-config-files behaves correctly against the real adapter but silently includes empty-content "samples" for every unlisted mock file in tests; harmless since the mock LLM ignores prompt content, but would matter for prompt-shape assertions. `server/src/adapters/mocks.ts:293`. (2026-09-28)
